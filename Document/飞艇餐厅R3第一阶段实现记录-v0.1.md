## 1. 本阶段结果

已建立 Finance、SceneLayout 与 BuildingConstruction 三个权威核心模块。新模块不改写旧 `M2Simulation`，目前通过 R1 的渐进迁移策略并行存在；后续 R3-04～R3-08 完成混合库存、仓储、餐盘和读模型切换后，再接入组合根与模块化存档。

## 2. Finance

主要实现：`packages/core/src/modules/finance/index.ts`。

- 全局铜币余额、有效资金预留和可用余额；
- 不可变经营流水和固定收支分类；
- 主动支出不允许余额变负，日薪等强制支出允许负余额；
- 资金预留创建、释放和转正式支出；
- 以稳定结算键去重的原子结算批次；
- 实时当日聚合与只读历史日结；
- 模块 schemaVersion、状态导出/恢复、操作 ID 去重；
- 作为 `TransactionalParticipant` 参与跨模块回滚；
- 每次余额、流水、预留、结算和跨日均产出领域事件。

## 3. SceneLayout 与 BuildingInstance

主要实现：`packages/core/src/modules/scene-layout/index.ts`。

- 全部业务几何只使用 2D 世界坐标；
- 场景合法区域标签、硬占地、视觉区域和必需交互区分离；
- 硬占地禁止重叠，但不注册为角色导航障碍；
- 只支持定义提供的预设朝向；
- BuildingInstance 保存稳定实例 ID、定义 ID、位置、朝向、样式、等级、耐久、启用、收起状态和累计投入；
- 能力组件 ID 由“建筑实例 ID＋定义槽位 ID”稳定派生，移动、换装和保留槽位升级不变；
- 移动提交后产生位置、交互点和连接路线变化事件；
- 升级重新验证目标布局，并由外部能力约束端口阻止忙碌、容量不足或引用中的能力移除；
- 必要设施不能收起或拆除；普通建筑收起保留实例身份，拆除后 ID 不复用；
- Y 排序只作为读模型派生值，不参与业务碰撞。

## 4. 建造预览事务

主要实现：`packages/core/src/modules/building-construction/index.ts`。

- 进入编辑模式必须通过暂停端口暂停模拟；
- 未解锁或资金不足时不创建预览；
- 每个收费预览创建时立即预留完整费用；多个预览共享 Finance 可用余额，不会超支；
- 免费奖励预览不创建资金预留；
- 指针位置更新只更新预览，不修改正式布局；
- 确认时重新检查解锁与布局，并在同一 `TransactionScope` 内提交“创建建筑＋预留转支出”；
- 位置竞态、预留失效或任一模块失败时全部回滚，随后释放预留并销毁失败预览；
- 取消预览和退出编辑模式会释放全部尚未确认预留；全部清理完成后才恢复模拟。
