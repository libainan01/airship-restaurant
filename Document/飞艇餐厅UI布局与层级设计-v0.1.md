# 飞艇餐厅 UI 布局与层级设计 v0.1

更新日期：2026-08-24  
状态：布局与信息层级方案已整理，等待确认后实施  
范围：桌面世界入口、管理窗口导航、功能面板层级和弹层规则；不改变现有业务模块

## 1. 当前问题

现有 UI 的松散感不是单纯来自按钮数量，而是入口、页面和弹层缺少共同父层级：

- 桌面世界只保留左上角“总览”按钮，仓库、食谱、采购、场景布置、科技树和员工等功能主要依赖场景热点直接打开。
- 管理窗口顶部一次陈列 8 个快捷入口，下面又混合经营总览、番茄钟、剧情花名册、设置和存档信息，形成过长的滚动页面。
- 仓库、食谱、采购、科技树、场景布置、员工和成长图鉴分别维护独立 open 状态，缺少“同一时间只有一个主功能”的约束。
- 故事花名册仍是页面滚动目标，不是稳定的一级功能路由。
- 设置、存档诊断、经营内容和剧情内容处在同一信息高度，玩家无法快速判断当前位于哪个层级。

## 2. 设计目标与边界

- 将统一功能入口放在桌面世界右下角，常态只显示一个折叠按钮。
- 展开后一次显示全部核心入口，不增加“先选分类、再选功能”的额外点击。
- 管理窗口改为一个统一壳层，同一时间只打开一个主功能。
- 场景内已经存在的仓库、交换站、服务中心等融合式热点暂时保留，点击后深链到同一个管理壳层，不复制面板实现。
- 普通经营面板不改变时间规则；场景编辑模式继续按既定规则暂停游戏。
- 本阶段只优化入口、布局和层级，不重写库存、采购、科技、员工等业务逻辑。

## 3. 桌面右下角折叠入口

### 3.1 折叠状态

- 固定在可用视口右下角，建议距右侧和底部各 16 px。
- 基准尺寸 52×52 px，Windows 高缩放下随 UI scale 调整，但不低于 44×44 px 可点击区域。
- 常态只显示“餐厅控制台”图标；只有需要玩家处理的阻塞或异常才显示角标，普通任务完成不累计角标。
- 原左上角“总览”按钮移除，避免双入口。

### 3.2 展开状态

- 菜单从按钮左上方展开，不越过右边缘或底边。
- 建议宽度 340–360 px，包含一条经营状态摘要和 4×2 功能格。
- 经营状态摘要本身可点击，进入“经营总览”，因此不占用第九个图标。
- 8 个功能直接可见；分类只做视觉分组，不额外增加一层导航。

功能分组：

| 分组 | 一级入口 | 说明 |
|---|---|---|
| 经营 | 仓库、食谱、采购、经营账本 | 高频经营信息和资源操作 |
| 人员与故事 | 员工、花名册 | 招募/日程与故事顾客进度 |
| 发展 | 场景布置、科技树 | 空间建设和长期成长 |

交互规则：

- 再次点击启动器、点击菜单外或按 Escape 收起。
- 点击功能后先收起菜单，再打开管理窗口的目标路由。
- 管理窗口已打开时，再从场景热点进入其他功能，只切换路由，不新开第二个管理窗口。
- 不使用只在 hover 时可见的入口；hover 只提供名称和一句短提示。

## 4. 管理窗口统一壳层

管理窗口不再以长页面作为主要导航。统一壳层分为四个区域：

1. 顶栏：当前功能名称、经营日期/资金摘要、保存状态、设置和关闭。
2. 左侧导航：经营总览及三组一级功能，始终保持固定顺序。
3. 主工作区：当前功能内容，同一时间只存在一个主路由。
4. 可选详情区：物品、角色、建筑等选中对象的检查器；在主工作区内部出现，不再打开另一张全屏弹窗。

推荐基准尺寸：

- 管理窗口内容宽度 900–1040 px，高度 620–720 px。
- 左侧导航 160–184 px。
- 顶栏 52–60 px。
- 详情检查器 280–340 px，仅在确有选中对象时出现。
- 低于 760 px 时左侧导航折叠成顶部下拉/横向入口，主区保持单列。

## 5. 功能信息架构

### 5.1 经营总览

- 今日收入、支出与净利润。
- 正在制作、运输、采购和等待处理的任务摘要。
- 番茄钟状态及开始/结束入口。
- 缺货、设备损耗、员工缺岗等需要处理的提醒。

经营总览只显示摘要，不在此直接复制完整仓库、采购或员工列表。

### 5.2 仓库

页签：库存、物流任务、库位配置。

- 原 WarehouseDialog 内容进入统一主工作区。
- 选中物品后在详情区显示所在位置、预定量、在途量和关联运输任务。
- 手动倒库存任务仍由仓库/物流任务页签创建。

### 5.3 食谱

页签：游戏食谱、现实做法、收藏。

- 简化食谱服务游戏流程。
- 详细食谱作为现实制作说明。
- 菜品详情在同一工作区右侧显示，不再层层弹窗。

### 5.4 采购

页签：自由采购、按食谱采购、自动补货。

- 本地采购与航线采购在页面内部使用二级分段或筛选，不再占用新的一级入口。
- 餐厅管理员解锁前，自动补货页签可见但显示解锁条件。

### 5.5 经营账本

页签：今日盈亏、分类明细、历史。

- 从经营总览抽离完整财务明细。
- 今日摘要可以被经营总览引用，但数据和实现只有一份。

### 5.6 员工

页签：员工名单、招募、职位、日程。

- RecruitmentDialog 合并进员工模块。
- 船长的飞艇冷却状态在角色详情区单独显示，不把船长逻辑塞进普通班表。

### 5.7 花名册

页签：故事顾客、收集进度、对话回顾。

- 当前 StoryRoster 从滚动卡片提升为独立一级路由。
- 普通顾客不进入故事花名册。
- ProgressionDialog 中与角色故事有关的内容迁入花名册；通用内容解锁迁入科技树的“解锁图鉴”。

### 5.8 场景布置

页签：建筑、家具、装饰、编辑模式。

- 进入编辑模式后关闭普通详情弹层并暂停游戏。
- 编辑工具条覆盖管理窗口的普通底部操作区，但不覆盖退出编辑模式的按钮。
- 已占用设备禁止拆除、允许换样式等既定规则保持不变。

### 5.9 科技树

页签：餐厅、物流、飞艇、招募、解锁图鉴。

- 原 TechnologyTreeDialog 进入统一主工作区。
- 通用内容成长与解锁图鉴并入科技树，减少单独的“成长与内容图鉴”入口。

## 6. UI 层级

| 层级 | 内容 | 行为 |
|---|---|---|
| L0 场景世界 | 飞艇、地面餐厅、角色、建筑、运输设施 | 游戏世界持续表现 |
| L1 常驻 HUD | 日期、资金、番茄钟、关键通知 | 不遮挡主要交互区，始终保持简洁 |
| L2 折叠启动器 | 右下角按钮与展开菜单 | 覆盖场景但面积受限，可随时收起 |
| L3 主功能面板 | 统一管理窗口与当前一级功能 | 同一时间只能有一个主路由 |
| L4 详情/编辑 | 物品详情、角色详情、建筑检查器、编辑工具条 | 依附当前主功能，不再独立堆叠全屏弹窗 |
| L5 确认/阻断 | 删除确认、资金确认、错误恢复、不可操作原因 | 仅用于需要明确决策的短流程 |
| L6 剧情/系统锁定 | 不可操作剧情对白、首次设置、严重存档恢复 | 优先级最高，暂时禁用普通管理输入 |

建议管理窗口内部 z-index 约定：主壳层 0、粘性顶栏 10、详情检查器 20、普通 popover 30、确认遮罩 50、系统阻断 80。桌面 Phaser 深度可以使用对应的独立范围，不要求和 DOM z-index 数值相同。

## 7. 关闭与返回规则

Escape 按由近到远的顺序处理：

1. 关闭确认弹窗。
2. 关闭局部详情或 popover。
3. 退出当前临时编辑工具；场景编辑模式需要二次确认时按既定规则处理。
4. 收起右下角菜单。
5. 关闭管理窗口。

不得一次 Escape 同时穿透多个层级。

## 9. 导航状态模型建议

不要继续为每个功能维护独立的 warehouseOpen、recipeBookOpen 等布尔值。建议使用单一导航状态：

- section：当前一级功能。
- tab：当前功能内部页签。
- selectionId：当前选中的物品、角色、建筑或节点。
- overlay：none、detail、confirm、blocking。

业务代码只根据稳定 section/tab 请求读模型；场景热点和右下角菜单都发送同一种导航请求。

## 10. 实施顺序

1. 扩展 ManagementSection，补齐 finance、roster 等稳定路由，并建立统一导航状态。
2. 将桌面左上角总览替换为右下角折叠启动器，保留场景热点深链。
3. 重构管理窗口壳层和左侧导航，但暂时复用现有各功能内容组件。
4. 逐项把 Dialog 内容迁入主工作区，移除多个独立 open 布尔值。
5. 拆分经营总览、系统设置、花名册和解锁图鉴的归属。
6. 补充键盘、窗口缩放、编辑模式和剧情锁定测试。

## 11. 验收标准

- 桌面常态只保留一个右下角功能入口，不再常驻一排功能按钮。
- 展开后最多一次点击即可进入八个核心功能中的任意一个。
- 场景热点和菜单入口打开的是同一功能路由与同一组件。
- 管理窗口不存在两个全屏功能弹窗同时打开的状态。
- 玩家始终能从顶栏和左侧导航判断当前位置。
- 1000×700 紧凑窗口中菜单不越界，启动器不遮挡重要系统提示。
- 760 px 以下布局无横向溢出，功能入口仍可键盘操作。
- 剧情锁定、编辑模式和确认弹窗不会被底层启动器抢占输入。
- UI 重构不修改库存、订单、任务、采购、科技、员工或存档业务数据。
