## 1. 本表范围

本表只统计视觉资源，不包含音乐、环境音和操作音效。资源分为：

- 场景与世界结构
- 可摆放建筑及功能设备
- 角色像素动画与对话立绘
- 食材、餐点、餐具和运输物
- UI 图标、面板装饰与功能插图
- 特效、环境动画和状态反馈
- 地域、航线与后续扩展素材

状态定义：

- 已接入：客户端正在直接加载的正式图片
- 仅参考：文件存在，但当前客户端未直接使用或不适合作为最终模块
- 程序占位：目前由 Phaser Graphics 或 CSS 绘制
- 缺失：尚无可使用资源
- 待设定：业务存在，但视觉对象或现实原型需要先确认

优先级定义：

- P0：下一版可视 Demo 必须具备
- P1：当前已实现玩法完整表现所需
- P2：成长内容、换装、地域扩展和表现增强
- P3：远期内容储备

## 3. 统一制作规格

| 项目 | 统一要求 |
|---|---|
| 镜头 | 2D 正视或轻俯视，不使用等距透视；同一场景保持一致地平线 |
| 场景逻辑尺寸 | 1920×1080 |
| 建筑占地单位 | 1 格 = 64×64 逻辑像素 |
| 像素缩放 | 整数倍缩放，NEAREST 过滤，禁止运行时平滑采样 |
| 角色建议尺寸 | 单帧画布 48×64 或 64×80；左右朝向共用一套并水平翻转 |
| 建筑导出 | 透明 PNG；原点统一为底部中心或左上角，占地与视觉外扩分开记录 |
| 图标建议尺寸 | 游戏图标母版 64×64；UI 同时导出 32×32 使用版 |
| 对话立绘 | 二次元非像素立绘，建议 1024×1024 透明 PNG；表情分层或独立导出 |
| 阴影 | 角色/可移动物体使用独立阴影，不把长阴影烘焙进主体 |
| 状态命名 | idle、active、occupied、damaged、repairing、disabled、preview |
| 外观命名 | default、brass；后续新增样式必须保持相同锚点与占地 |
| 文件命名 | 全小写英文 ID，使用连字符；禁止以“最终版2”等人工版本名进入资源目录 |
| 源文件 | 保留 Aseprite/PSD 分层源文件；运行时只提交裁切后的 PNG/atlas |
| 透明边界 | 裁切透明空白，但必须保留统一锚点数据，避免换状态时跳动 |

建议目录：

- assets/world/
- assets/buildings/{building-id}/{style-id}/
- assets/characters/{character-id}/pixel/
- assets/characters/{character-id}/portrait/
- assets/items/ingredients/
- assets/items/dishes/
- assets/ui/icons/
- assets/ui/frames/
- assets/vfx/
- assets/regions/

## 13. 单项验收标准

每个资源完成时至少检查：

- 是否符合正视/轻俯视 2D 镜头，不混入透视版构图。
- 是否使用透明背景并正确裁切。
- 是否符合 64 像素占地网格及约定锚点。
- idle、active 等状态切换时是否不跳位。
- 水平翻转后工具、徽章和文字是否不会镜像错误。
- 在 100%、125%、150% Windows 缩放下是否保持清楚。
- NEAREST 缩放时是否没有灰边和半透明脏像素。
- 深色与浅色背景上是否都能辨认轮廓。
- 同一建筑的 default/brass 样式是否保持完全相同碰撞占地。
- 文件 ID 是否与内容目录中的 building、character、ingredient、recipe ID 对应。
- 是否提供源文件、导出文件、缩略图和预览图。
- 食材与菜品是否对应现实可制作原型。
