# 飞艇餐厅 R10 产品缺口收口实现记录 v0.1

更新日期：2026-08-20  
状态：已完成

## 1. 目标

R9 已把正式客户端收敛为唯一经营世界。R10 不再建立新架构，而是把此前已经存在于领域模块、但没有完全进入产品交互或正式流程的能力补齐，并用内容、读模型、UI 和表现反馈形成玩家可以直接体验的闭环。

本阶段不读取或修改玩家正式存档；所有运行验证继续使用隔离 userData。

## 2. 正式维修与耐久

- 小型货梯受损后使用与损坏生命周期绑定的稳定维修任务 ID，同一次损坏不会重复发布任务，下一次损坏不会复用旧任务。
- 新增正式货梯维修流程，维修任务进入统一 Task 模块，仅具备维修资格且在岗的员工可以领取。
- 维修速度由角色修理能力决定；完成后修复货梯并发布通用任务完成广播，UI、声音和统计可订阅结果。
- 奥托已具备维修职位能力，基础 Demo 即使没有额外招募维修员也不会因货梯损坏永久停摆。

## 3. 剧情顾客好感度

- 正式产品组合根接入 StoryRosterCustomerEventAdapter，不再只依赖核心模块测试。
- 剧情顾客首次真实到店时发现花名册角色；餐点真实消费后，按菜品质量增加好感度。
- 闲聊仍不增加好感度；重复事件 ID 不重复记分。
- 适配器只订阅正式 Customer、KitchenProduct 和共享事件总线，不建立第二份顾客或餐点状态。

## 4. 建筑购买、布置与外观

- InstanceUpgrades 协议新增建造目录、建造预览和建筑空间状态。
- 玩家必须先进入编辑模式；编辑期间游戏暂停。
- 资金不足时不能创建预览。创建预览立即预留建造款，取消或退出编辑模式释放预留，确认后转为正式 building-purchase 支出。
- 支持更新预览坐标、确认建造、移动已有建筑和切换允许的外观。
- 临时预览不写入正式存档；异常重启时只释放 sourceType=building-preview 的遗留预留，不影响建筑升级预留。
- 建造价格、可选样式、默认样式和生命周期标记已经下沉到建筑内容目录；桌面主进程不再维护第二份价格表。
- 11 种建筑均提供 default 与 brass 两种演示外观，必要建筑由内容数据明确标记。

## 5. 玩家手动运输队列

- 新增正式 ManualLogisticsRuntime，通过既有 LogisticsDemandModule 创建玩家指定的交换站运输组。
- 手动需求仅允许在地面交换站与飞艇交换站之间建立；每成功运输一件，剩余数量减一。
- 相同方向、反方向或完全相同的多个订单保持为独立队列，不自动合并，也不禁止玩家来回倒库存。
- 支持停止队列；在途物品继续走既有货梯领取与完成流程。
- 仓库 UI 可选择来源、目标、物品和数量，并显示已送、待运、在途、阻塞原因与停止操作。

## 6. 仓库与双层食谱

- 新增独立仓库入口和对话框，按食材、餐具、半成品、餐点统计总量、预留与在途数量。
- 每个真实库存位置显示容量、占用、分类和堆叠物品；餐盘洁净循环单独展示。
- 新增独立食谱入口，只展示已解锁菜品。
- 游戏层展示简化配料、售价、产量、DAG 步骤、并行/前置关系、设备和是否需要厨师在场。
- 现实层展示真实菜名、人数、完整配料表、制作步骤和安全/制作提示；调味品只存在于现实食谱，不进入游戏库存。

## 7. 表现反馈

- 桌面表现层新增轻量事件音效，订阅顾客到店、点单、厨房通知、上桌成交、离店和采购到货。
- 声音使用 Web Audio 即时合成，不引入受版权约束的外部音频素材。
- 首次读取存档只建立事件基线，不重播历史声音；安静模式下新事件会被标记为已见，不会退出安静模式后集中补播。
- 音频只属于 renderer 表现，不反向影响任务、订单或事件完成。

## 8. 关键结构修正

- BuildingConstructionModule 丢弃预览时 revision 从错误的重置为 1 改为正常递增，避免后续读模型因 revision 回退而拒收更新。
- 建造界面在所有建筑均满级时仍可从任意已放置建筑推导编辑场景，不依赖存在可升级实例。
- 独立仓库、食谱和建造界面已加入隔离烟雾测试的实际打开、内容断言与视觉截图。

## 9. 验收结果

- `npm run check` 通过：冻结护栏、依赖边界、文档状态、内容一致性、全部 workspace 类型检查和生产构建均成功。
- 全仓 130 个测试文件、578 项 Vitest 与 4 项对白工具测试通过；新增音效去重测试随后单独复验通过。
- `npm run smoke` 使用隔离 userData 成功恢复完整运营模块；Desktop 与 Management 两个 renderer 均进入 ready，新仓库、现实食谱和建造界面被实际打开并通过内容断言。
- `npm run smoke:transparency` 通过：飞艇与地面餐厅 alpha=255，两处空白区域 alpha=0。
- 视觉记录：
  - `Document/r10-warehouse-management.png`
  - `Document/r10-recipe-book-management.png`
  - `Document/r10-building-management.png`
- 视觉复查后修正仓库横向溢出、库位排序、角色携带标签和餐盘中文名；现实食谱记录直接展示完整配料与现实制作步骤。
- 30 秒 Windows 隔离常驻抽样共 7 个样本：renderer 始终为 2，存档错误样本为 0，renderer 退出、主帧加载失败和桌面恢复均为 0；运行时与业务 revision 均增加 29。
- 常驻内存在 renderer/GPU/utility 首次出现后的 6 个样本维持在 626,908—643,640 KB，末值 634,288 KB，没有持续上升趋势；峰值合计 CPU 1.89%。
- 所有 smoke、视觉与常驻验证只使用临时隔离目录，未读取或修改玩家正式存档。
