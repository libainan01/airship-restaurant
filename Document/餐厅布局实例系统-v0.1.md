# 《空艇餐厅》餐厅布局实例系统 v0.1

更新日期：2026-07-31

## 1. 目标

餐厅中的桌子、窗户、立柱、吊灯、柜台不再只是 `WorkspaceScene` 里的硬编码绘制坐标；
入口、出口、普通座位、对话站位、奥托待命点和取送餐点也不再由 NPC 状态机自行写死。
同一份布局定义同时服务画面绘制和 NPC 行为，避免更换美术或移动家具后角色仍走向旧坐标。

当前系统负责“餐厅内部表现布局”。餐厅整体仍是一个贯穿屏幕底部的连续点击区域，布局物件、
角色、关系线和气泡不会单独注册 `SemanticHitMap` 热区，因此不会扩大或切碎桌面点击范围。

## 2. 三类实例

### 2.1 布局物件实例（Prop）

每个可见物件拥有稳定 `id`，并记录：

- `kind`：立柱、窗户、桌子、柜台或吊灯；
- `visualKey`：以后替换程序占位图、精灵或动画时使用的资源键；
- `transform`：相对餐厅的横纵比例、像素偏移和原点；
- `dimensions`：像素尺寸、比例尺寸及尺寸修正；
- `renderLayer`：背景、家具或灯光层；
- `capabilities`：结构、座位、服务、照明、可升级等能力；
- `tags`：供编辑器、升级系统和内容筛选使用；
- `enabled`：为布局变体、设施开关和升级阶段预留。

功能位置可以通过 `parentPropId` 指向所属物件。例如普通中桌座位属于
`prop.table.center`，奥托取餐点属于 `prop.counter.service`。运行时启动时会校验引用，
避免删除桌子后遗留一个悬空座位。

### 2.2 功能锚点实例（Anchor）

锚点是不需要占用的任务目的地，当前包括：

- `guest-entry` / `guest-exit`：客人的进店与离店位置；
- `otto-home`：奥托待命和送餐返回位置；
- `otto-pickup`：奥托取餐位置；
- `delivery-table`：奥托放下餐点的位置。

锚点保存二维位置与朝向。NPC 只按角色查询锚点，不知道默认布局中的具体比例值。

### 2.3 可预订位置实例（Position Slot）

普通座位和对话站位都是可预订的位置实例，包含稳定 ID、二维位置、朝向、优先级、
所属物件及冲突位置列表。布局运行时维护“位置—NPC”与“NPC—位置”的双向占用关系。

多人对白使用显式编队实例。当前预置 2—5 人编队；单人闲聊会加入奥托作为倾听者，
因此实际申请 2 人编队。整组位置会原子预订：要么全部成功，要么不移动任何人。
对话站位与中桌普通座位互相冲突；系统会优先把占用冲突座位的客人选为对话参与者，
防止重叠或临时闪现。

## 3. 当前默认实例

| 类别 | 默认实例 |
| --- | --- |
| 物件 | 4 根立柱、3 扇窗、3 张桌、1 个服务柜台、2 盏吊灯 |
| 锚点 | 客人入口、客人出口、奥托待命点、奥托取餐点、送餐落点 |
| 普通位置 | 左桌、中桌、右桌各 1 个座位 |
| 对话位置 | 5 个桌边站位，组合为 2、3、4、5 人编队 |

定义位于 `apps/desktop/src/renderer/desktop/restaurant-layout.ts`。`WorkspaceScene` 遍历物件
实例绘制占位图，`RestaurantNpcProjector` 通过同一个 `RestaurantLayoutRuntime` 查询
功能位置；位置占用事实由 core 业务模块决定。角色帧同时输出 `xRatio`、`yRatio` 和 `positionSlotId`，气泡与关系线跟随
角色的真实二维位置。

## 4. 后续扩展方式

### 更换美术但布局不变

保留物件 ID 与功能位置，只替换 `visualKey`，并根据素材留白调整物件 `transform`、
`dimensions`。NPC 行为无需修改。

### 移动桌子或修改座位

同步调整桌子物件和以它为 `parentPropId` 的座位、对话位置。NPC 下一次构建布局运行时
会直接使用新坐标；不需要修改状态机中的数字。

### 新增桌子和客容量

新增桌子物件实例，再新增一个或多个 `seat` 位置并指向该桌子。普通客人数量会按可用
普通座位实例初始化，空座由运行时按 `priority` 分配。

### 餐厅升级与布局变体

后续升级系统可以生成新的 `RestaurantLayoutDefinition`，利用稳定 ID 保留物件身份，
通过 `enabled`、`visualKey`、能力标签和位置集合改变设施阶段。布局热切换前需要增加
“迁移现有占位—重建表现—刷新命中地图”的流程；v0.1 只在场景会话开始时构建布局，
暂不支持营业中热切换。

### 独立布局编辑工具

后续工具只需编辑布局定义并执行与运行时相同的校验：ID 唯一、比例合法、父物件存在、
冲突位置存在、对话编队人数与位置数量一致。可视化编辑器无需理解 NPC 状态机。

## 5. 生命周期和存档边界

- 布局定义是内容数据；位置占用是当前在线会话的表现状态；
- NPC 离店、对话结束和任务切换都会释放对应预订；
- 位置占用、角色坐标和临时行为不写入经营存档；
- 经营层仍只保存库存、订单、销量、铜币、故事等事实；
- 离线结算不会创建 NPC、预订座位或播放对白。

## 6. 已有验证

- 默认物件、锚点与父物件引用可被稳定查询；
- 普通座位按优先级预订、释放并复用；
- 对话编队会从普通座位原子迁移参与者并处理冲突位置；
- 缺失父物件引用会在布局构建时立即失败；
- NPC 导演在入口、座位被改到自定义坐标后会跟随新布局移动，证明不再依赖内置坐标。
