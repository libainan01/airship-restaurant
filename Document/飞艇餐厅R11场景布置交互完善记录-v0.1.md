# 飞艇餐厅 R11 场景布置交互完善记录 v0.1

更新日期：2026-08-20  
状态：已完成

## 1. 目标

R10 已接通建筑购买、预扣款、建造预览、移动和换样式，但产品入口仍以“设施升级”命名，核心操作依赖 X/Y 坐标表单，玩家无法自然发现“怎么摆放”。R11 将建筑摆放改为符合 2D 平面游戏直觉的可视化流程。

本阶段不读取或修改玩家正式存档；Electron 验证全部使用隔离 userData。

## 2. 玩家入口与流程

- 经营管理快捷入口从“设施与载具升级”改为“场景布置”，说明文字明确展示“拖拽摆放”。
- 对话框改名为“场景布置与设施升级”，建造能力置于首屏，载具与实例升级仍保留在同一面板下方。
- 主流程固定为：选择设施、放入场景、拖动位置、确认建造。
- 资金不足时“放入场景”按钮不可用，不创建预览，也不预留资金。
- 进入编辑模式后游戏暂停；关闭面板或退出编辑模式会继续沿用已有的安全取消与预留释放流程。
- 原 X/Y 输入降级为折叠的“精确坐标微调”，不再是主要入口。

## 3. 2D 拖拽画布

- 新增 16:9 场景俯视布置图，逻辑坐标固定为 1920×1080，随管理窗口等比缩放。
- 画布展示飞艇厨房、人员/货物升降区、地面餐厅三个区域，已有建筑和建造预览都按真实占地绘制。
- 指针位置统一换算为逻辑场景坐标，并以 16 像素网格吸附。
- 新预览自动在允许区域中寻找空位；拖动时限制在所属物理区域和场景边界内。
- 松开已有设施后调用正式移动命令；核心校验拒绝时，画布恢复权威位置并提示无法摆放。
- 预览合法时显示绿色，碰撞或其他校验失败时显示红色并禁用确认。
- 小型设备使用短名称，完整名称、坐标、外观与操作集中显示在选择面板，避免画布内信息拥挤。

## 4. 场景与读模型修正

- 桌面场景不再让 zone.airship、zone.edge、zone.ground 三个标签共同覆盖整张画布。
- 正式物理区域划分为：飞艇 0—448、升降区 448—640、地面 640—1080。
- 默认 14 个设施实例均处于对应合法区域；新增回归测试阻止地面设施放入飞艇、飞艇设施放入地面。
- InstanceUpgrades 读模型为目录和已有建筑公开 allowedRegionTags、当前 footprintWidth 与 footprintHeight。
- renderer 只根据读模型表现和发命令，不建立第二份建筑位置或资金状态。

## 5. 验收结果

- npm run check 通过：131 个测试文件、582 项 Vitest 与 4 项对白工具测试全部成功，架构、文档、内容、类型检查和生产构建通过。
- 新增坐标缩放、区域吸附、边界限制、自动空位和百分比布局测试。
- npm run smoke 使用隔离 userData，实际完成“打开场景布置 → 进入编辑模式 → 从设施库放入预览”，并断言预览真实出现在画布。
- npm run smoke:transparency 通过：飞艇与地面餐厅保持不透明，两处场景空白保持透明。
- 视觉记录：Document/r11-scene-placement-management.png。
- 所有运行验证只使用临时隔离目录，未读取或修改玩家正式存档。
