# 飞艇餐厅 R0 重构基线 v0.1

> 状态：R0 基线盘点。本文只记录当前可观察行为和旧写入路径，不认可旧结构为最终设计。

> 历史阶段记录：文中的“当前”特指 2026-08-17 的 R0 冻结基线。旧经营聚合、总快照桥接和 renderer 业务协调器已在 R8 删除；当前实现见《飞艇餐厅当前技术架构 v0.1》。

## 1. 公开运行时边界

当前所有窗口通过 `RuntimeBridge` 读取一个全量 `GameSnapshot`，并通过 `GameCommand` 向主进程提交命令。主进程中的 `GameRuntime` 是命令入口和快照发布者。

### 1.1 当前命令

| 命令 | 当前处理者 | 当前权威数据 | 计划迁移阶段 |
|---|---|---|---|
| `settings.set-quiet-mode` | `GameRuntime` | Runtime settings | R7（专注模式） |
| `gameplay.select-recipe` | `M2Simulation` | Cooking + Restaurant | R5 |
| `gameplay.set-auto-repeat` | `M2Simulation` | Cooking | R5 |
| `gameplay.purchase-upgrade` | `M2Simulation` | 聚合升级状态 | R7 |
| `gameplay.place-procurement-order` | `M2Simulation` / `ProcurementSystem` | Procurement + Finance/Restaurant | R6/R7 |
| `gameplay.configure-procurement-automation` | `M2Simulation` / `ProcurementSystem` | Procurement | R7 |
| `narrative.mark-viewed` | `NarrativeSystem` | Narrative | R7 |
| `narrative.complete` | `NarrativeSystem` | Narrative | R7 |
| `story.replay-dialogue` | `StorySequenceSystem` | Story | R7 |
| `dialogue.request-ambient` | `AmbientDialogueSystem` | Dialogue | R4/R7 |
| `presentation.start-demo` | `PresentationDemoSystem` | Presentation demo | R6 后删除正式业务依赖 |
| `presentation.stop-demo` | `PresentationDemoSystem` | Presentation demo | R6 后删除正式业务依赖 |

当前命令结果固定为 `accepted` 或带拒绝码的 `rejected`，命令 ID 在内存中保留最近 512 个以拒绝重复提交。R0 命令夹具位于 `packages/test-support/fixtures/r0/command-results.json`。

### 1.2 当前全量快照

`GameSnapshot` 当前包含：

- Runtime：`revision`、`phase`、`runtimeStartedAtUtcMs`、`settings`；
- 经营：`gameplay`、`restaurantActivity`；
- 内容流程：`narrative`、`dialogue`、`story`、`presentationDemo`；
- 离线结果：`offlineEarnings`。

R1 先保留该快照作为兼容投影；R6 迁移窗口到分片读模型；R8 删除旧总快照业务依赖。

## 4. 当前存档边界

当前游戏存档为用户数据目录中的 `save.json`：

- 信封版本：`schemaVersion: 1`；
- 载荷：`M2SimulationState`，可选 `narrative` 与 `story`；
- 写入：先写 `save.json.tmp`，再备份旧主档为 `save.json.bak`，最后替换主档；
- 读取：主档有效则读取主档；主档无效时尝试备份；两者都无效时建立新进度；
- `settings.json` 独立于游戏存档。

固定样本位于 `packages/test-support/fixtures/r0/saves/`，覆盖：新进度、经营中、运输中、剧情中、损坏主档和备份恢复。样本是迁移输入，不是未来存档格式。

## 5. 确定性与表现基线

- 经营确定性：同一状态的一次推进、分段推进和序列化恢复结果相同；8 小时固定摘要位于 `packages/test-support/fixtures/r0/determinism-summary.json`。
- Phaser 表现：现有 `restaurant-npc-director`、移动、座位、对话、奥拓服务和功能热点测试作为 R0 特征测试；它们描述当前表现，不赋予 renderer 未来业务所有权。
- 2026-08-17 首次运行 R0 完整检查时，发现飞艇上移后工程升级热区顶部为 `-1.48`。R0 仅把点击热区限制在视口内，不改变飞艇图像位置。

## 6. R0 冻结规则

1. 不向 `M2Simulation` 或 renderer 遗留协调器增加新玩法。
2. 不新增 renderer `Coordinator`、`Queue` 或 `Director` 作为业务权威状态。
3. `M2Simulation` 只能由已登记的主进程装配入口和既有测试直接实例化。
4. 遗留名单在后续阶段只能缩小；如确需临时扩大，必须同时更新架构文档、任务证据和迁移阶段。
5. R0 夹具默认只读；更新必须说明是修复了错误基线，还是经过确认改变了需求。
