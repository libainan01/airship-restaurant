## 1. 新增目录与公开出口

`packages/core/src` 新增以下边界：

- `kernel/`：命令、事件、同步事务与 Process Manager；
- `modules/`：领域模块公共契约；
- `runtime/`：运行时模块注册；
- `projections/`：带独立 revision 的读模型注册表；
- `compatibility/`：旧 `GameRuntime` 命令和总快照兼容门面。

这些目录都通过各自 `index.ts` 和 core 根出口公开。`scripts/check-dependency-boundaries.mjs` 禁止 renderer 导入 core，并阻止外部绕过新目录公开出口导入内部文件。

## 2. Kernel 行为

### 2.1 CommandBus

- 注册式命令路由；
- 结构与载荷校验；
- 命令 ID 有界去重；
- 区分成功变更、成功无变化、业务拒绝、无效命令、未知命令和重复命令；
- 处理器抛出意外异常时不消费命令 ID，允许显式恢复后重试。

旧 `GameRuntime.dispatch` 暂不迁移，避免在 R1 引入第二份权威命令状态。后续领域模块逐个切换写入时使用新 CommandBus。

### 2.2 TransactionScope

每个参与模块创建独立事务会话：

1. 建立模块暂存状态与回滚检查点；
2. 执行业务工作并缓存待发事件；
3. 在提交前校验全部事件和全部模块；
4. 按顺序提交全部模块；
5. 所有提交成功后才同步发布事件；
6. 任一步骤失败时逆序回滚所有已经开始的会话。

事件订阅失败由 DomainEventBus 隔离，不回滚已经提交的源事实；参与者提交失败则仍回滚更早提交的参与者。

### 2.3 DomainEventBus

- 同步按事件类型或通配符订阅；
- 稳定事件 ID 有界去重；
- 发布整批事件前先完成全量校验；
- 订阅者异常计数并通过错误回调报告，不中断其他订阅者。

### 2.4 ProcessManager

- 保存 manager ID、definition ID、schemaVersion、revision、业务状态和已处理事件 ID；
- 同一事件恢复后重复投递不会再次产生命令；
- 转换结果只返回后续命令，不直接取得其他模块可变实例；
- 不识别的事件同样记入有界幂等历史，避免恢复后无限重试。

## 3. 分片读模型与模块注册

`ReadModelRegistry` 为每个 key 保存独立 revision、当前完整值和订阅列表。窗口或 Presenter 可以先读取当前切片，再订阅后续变化，不需要从事件流重放长期界面状态。

`RuntimeModuleRegistry` 以稳定 module ID 注册模块公共对象；重复注册被拒绝，调用方只能获得模块公开契约。

## 4. 旧 Runtime 兼容门面

主进程仍由原 `GameRuntime`、`M2Simulation` 和现有存档负责经营事实。`LegacyGameRuntimeCompatibility`：

- 命令直接转发给旧 Runtime；
- 将旧 `GameSnapshot` 投影到 `compatibility.game-snapshot` 读模型切片；
- 通过切片向 IPC 提供读取和订阅；
- 不保存或修改任何经营领域状态。

`IpcRouter` 已改为依赖 `LegacyGameRuntimePort`。定时推进、保存、离线计算和稳定性监控仍使用原 Runtime，因此不存在新旧双写。
